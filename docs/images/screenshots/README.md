# Screenshots

The images the READMEs and wiki pages embed. They live here — not in the sample's generated output —
so a documentation link never breaks when a diagram is regenerated.

| File | Shows | Used by |
| --- | --- | --- |
| `architecture-diagram.png` | the LikeC4 architecture diagram generated by `AddAspireC4()` for the sample AppHost, with a group, relationships and per-resource technologies | root `README.md`, `docs/wiki/Home.md`, `src/src/AspireC4/README.md` |
| `entity-framework-er-diagram.png` | the interactive ER diagram from `WithEntityFrameworkDiagram()`, one group per `DbContext`, key badges and relationship edges | root `README.md`, `docs/wiki/Home.md`, `docs/wiki/Entity-Framework-Diagrams.md`, `src/src/EntityFrameworkCore/README.md` |

## Refreshing them

Both are captured from the sample AppHost at `src/src/TestAppHost`:

```sh
dotnet run --project src/src/TestAppHost
```

That run exports the architecture view as one PNG per view (`architecture-index.png`, …) and the ER diagram
as `schema.svg` / `schema.png`, which is the d2 render. The image used here is the **interactive viewer**
instead: capture it with the viewer's own **Save as PNG** button, or turn on `UseViewerFidelityExport` to
have the AppHost produce the identical file. Copy whichever you want over the file here, keeping the name
above so no documentation link has to change.

If a file has to be renamed, update every reference. The paths appear in:

- `README.md`
- `docs/wiki/Home.md`
- `docs/wiki/Entity-Framework-Diagrams.md`
- `src/src/AspireC4/README.md`
- `src/src/EntityFrameworkCore/README.md`

## Rules

- **Relative links** from the root `README.md` (`docs/images/screenshots/<file>`).
- **Absolute `raw.githubusercontent.com` URLs** from `docs/wiki/*.md`, because the wiki is published from a
  separate repository, and from package READMEs, because relative links do not resolve on nuget.org.
- Skills under `skills/` are installed on their own, so they never embed these files — name the export
  folder (`./.aspirec4/images/`) in prose instead.
